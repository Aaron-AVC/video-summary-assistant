# V1.1 Side Panel Decomposition Design

**Date:** 2026-10-19
**Project:** Video Summary Assistant
**Design status:** DESIGN PASS
**Authority:** `b76f12375c2d7019ad2f29be9ef72962ea084230`

## 1. Executive Summary

V1.1 should decompose `src/sidepanel/index.tsx` by responsibility and ownership, not by line count. The file is currently a high-coordination React boundary: it owns the active workspace projection, history selection, transcript loading, Analysis and Ask invocation, task presentation, deletion coordination, runtime timestamp actions, storage handoff, and i18n-facing UI composition. The underlying domain boundaries already exist and should remain authoritative: `AnalysisTaskController`, `AskTaskController`, the platform adapters and content bridge, `historyRepository`, `qaConversationRepository`, `settingsStorage`, and the i18n synchronizer.

The target is a thin root that composes a workspace controller, feature controllers, and presentation sections. The runtime bridge remains the sole authority for the browser's current content; the workspace controller consumes runtime-content transitions and owns shared selection/publication coordination, but does not become a repository facade or a universal React context. Feature controllers own feature workflows and expose typed snapshots/events. React components may subscribe to the workspace and feature snapshots, but do not access IndexedDB or browser messaging directly.

The recommended first refactor is Stage 1 only: add characterization tests and extract `formatTimestamp`, `identityFromContext`, `identityFromAnalysis`, and already-stable pure identity/comparator/publication helpers with explicit inputs and outputs. Task-presentation extraction is Stage 2, navigation boundary extraction is Stage 3, and transcript workflow extraction is Stage 4. Workspace state ownership moves last. No V1.1 feature is implemented by this document, and no V1 release gate is reopened.

## 2. Current Architecture Inventory

### 2.1 Root composition and UI state

`SidePanel` at `src/sidepanel/index.tsx:1862-1869` composes `I18nProvider`, `ExtensionProviders`, and `SidepanelWorkspace`. `SidepanelWorkspace` owns `activeTab` (`:182`), provider projection (`:183`), analysis projection (`:184`), recent history (`:185`), transcript state (`:186-192`), Ask state (`:193-198`), boot/loading/error state (`:199-202`), task snapshots (`:204-215`), generation refs (`:216-225`), and destructive-operation workspace metadata (`:226-243`).

The tab components are already presentation-oriented: `OverviewTab`, `TranscriptTab`, `AskTab`, `SettingsTab`, and `SidePanelShell` receive data and callbacks at `:1745-1856`. The root still computes nearly every callback and cross-feature precondition before passing them down.

### 2.2 Workspace identity and current video

- `useRuntimeBridge()` supplies `activeTabId`, `videoContext`, runtime `status`, `refreshCurrentVideo`, and `jumpToTimestamp` (`:178`).
- `videoContextRef` (`:179-180`) preserves the latest runtime identity for asynchronous completion paths.
- `identityFromContext` (`:157-165`) and `identityFromAnalysis` (`:167-173`) project `platform`, `videoId`, optional `partId`, and canonical `contentKey` into `VideoIdentity`.
- `title`, `canonicalUrl`, `workspaceTask`, `hasMatchingTranscript`, and `isExactCurrentDisplayedAnalysis` (`:295-353`) are derived workspace selectors.

This is domain identity plus UI projection. The canonical identity contract is defined by `src/features/platform/types.ts`, runtime schemas in `src/lib/runtime/messages.ts:185-208`, and the persistence documentation: YouTube uses `youtube:<videoId>` and Bilibili uses `bilibili:<bvid>:p:<N>`.

### 2.3 Transcript state and acquisition

State is held in `transcriptCues`, `transcriptIdentity`, `transcriptTitle`, `currentTranscriptFingerprint`, `rawVtt`, `transcriptError`, and `isTranscriptLoading` (`:186-192`).

- `loadTranscriptForCurrent` (`:692-806`) captures `requestedContentKey`, increments `transcriptLoadGenerationRef`, reuses session/cache data through `resolveCurrentTranscript`, invokes `loadCurrentTranscript` for remote work, computes the fingerprint, persists the transcript cache, and clears Ask state when the fingerprint changes.
- `loadTranscriptForTask` (`:818-903`) repeats the same policy for an Analysis task, adding captured `sourceTabId` and `analysisTaskController.isCurrent(taskId)` checks.
- `handleLoadTranscript` (`:808-816`) is the UI command wrapper.
- Runtime `FETCH_VIDEO_TRANSCRIPT` orchestration is split correctly below the Side Panel: `load-current-transcript.ts` validates the response and `platform-content-bridge.ts:148-205` delegates to the resolved platform adapter, checks initial/current identity, and rejects a changed video part.

The root currently owns the final state publication and persistence call. That publication should move behind a transcript workflow controller without moving parsing or adapter logic into React.

### 2.4 Analysis state, lifecycle, and persistence

Analysis UI state is `analysisView`, `analysisPhase`, `analysisError`, `isAnalysisFetching`, and `isBootstrapping` (`:184`, `:199-202`). The task lifecycle itself is already independent in `AnalysisTaskController` (`src/features/analysis/lib/analysis-task-controller.ts:42-107`): one active task, immutable snapshot, AbortController, phases, subscription, `isCurrent`, and non-cancellable `finalizing`.

`handleAnalyze` (`:905-1233`) still coordinates admission, task start, transcript loading, fingerprinting, provider resolution, cache lookup, `runAnalysis`, finalizing persistence, task cancellation/error presentation, and current-workspace publication. `analysis-task-lifecycle.ts:6-27` supplies cache/reload policy, completion timestamps, and `shouldPublishAnalysisToWorkspace`.

The controller owns task identity and cancellation. A future Analysis feature controller should own the workflow runner and persistence adapter calls, while React receives task snapshots and a small command surface (`generate`, `regenerate`, `cancel`).

### 2.5 Ask state, conversation, and lifecycle

Ask UI state is `askQuestion`, `askAnswer`, `qaThreadId`, `qaThreads`, `qaMessages`, and `askError` (`:193-198`). `AskTaskController` is already independent (`src/features/analysis/lib/ask-task-controller.ts:44-109`) with one active task, immutable content/analysis/transcript/thread/provider identity, phases, AbortController, and cancellation semantics.

The root still owns:

- conversation restore (`restoreQaConversation`, `:253-285`);
- Ask preflight and identity capture (`handleAsk`, `:1354-1612`);
- thread open/new/delete (`:1618-1675`);
- QA cache reads/writes and message append calls;
- stale checks using `askGenerationRef`, `qaLoadGenerationRef`, `activeQaThreadIdRef`, `activeAnalysisContentKeyRef`, `activeAnalysisRunIdRef`, and `currentTranscriptFingerprintRef`.

`qaConversationRepository` is a React-free persistence boundary. It validates thread/message rows, sequences messages transactionally, and filters by canonical `contentKey` and `analysisRunId` (`src/features/analysis/lib/qa-conversation-repository.ts:36-142`). The future Ask feature controller should own conversation workflow, not the root component.

### 2.6 History state and restore

`refreshRecentAnalyses` (`:355-372`) maps `historyRepository.listRecentAnalyses` into UI items. Three restore paths exist:

- active/legacy video restore: `loadSavedAnalysis` (`:451-510`);
- current canonical context restore: `loadSavedAnalysisForContext` (`:512-570`);
- exact historical run restore: `loadSavedAnalysisRun` (`:572-626`).

`handleOpenSavedAnalysis` (`:1239-1266`) increments invalidation generations, clears Ask presentation, chooses the appropriate restore path, and reports success. `historyRepository` owns aggregate reads such as `getCurrentAnalysisByContentKey`, `getSavedAnalysisRunById`, transcript lookup, recent listing, and destructive operations (`src/features/history/lib/history-repository.ts:273-307`, `:437-515`, `:529-575`, `:576-714`).

Restore is a history feature command that asks the workspace controller to publish a selected historical snapshot. It is not a root-level ad hoc state mutation.

### 2.7 Navigation and timestamp jumps

`formatTimestamp` (`:145-155`) is a pure presentation helper. `jumpWithIdentity` (`:1677-1695`) calls the runtime bridge with a `VideoIdentity`, handles the result, and displays a toast. `handleAnalysisJump` and `handleTranscriptJump` (`:1697-1706`) choose the source identity.

The platform adapter owns native seek and platform-specific URL semantics (`docs/platform-architecture.md:14-18`). The runtime bridge owns cross-surface message transport (`src/lib/providers/extension-providers.tsx:149-161`). A small navigation service should own identity-aware jump orchestration and result normalization; it must not duplicate adapter seek logic.

### 2.8 Provider/settings state

The root stores only the metadata projection of the default provider (`provider`, `:183`). `loadWorkspace` (`:628-663`) reads `settingsStorage.getProviderConfigs`; `handleProvidersChange` (`:1721-1723`) updates the projection. `SettingsTab` reuses provider UI and returns metadata-only changes. `settingsStorage.resolveProvider` remains the privileged boundary immediately before an AI request; API keys do not belong in workspace state or React drafts.

### 2.9 Runtime messaging and external events

`ExtensionProviders` centralizes runtime requests, active-tab refresh, `ACTIVE_VIDEO_CONTEXT_CHANGED`, tab activation/update listeners, and timestamp jump (`src/lib/providers/extension-providers.tsx:101-213`). The Side Panel root additionally watches `chrome.storage.local` for `PENDING_HISTORY_OPEN_KEY` (`:1315-1352`) and consumes cross-surface history selection.

The storage handoff belongs to a history/workspace adapter, not to a feature panel. Runtime listeners should remain in `ExtensionProviders` or a dedicated runtime controller; individual panels should not attach `chrome.runtime` or `chrome.tabs` listeners.

### 2.10 Concurrency and destructive data management

Analysis and Ask admission uses `admitDestructiveTask` and `subscribeToDestructiveOperations` (`:414-449`, `:946-952`, `:1427-1435`). `destructive-operation-coordinator.ts` distinguishes Web Locks for admission/reservation from BroadcastChannel for cross-surface discovery/propagation (`:153-218` and the V1 audit). `applyMutation` (`:374-412`) invalidates generations and clears dependent UI projections after repository mutations.

This coordination is not ordinary UI state. It should be exposed as a workspace invalidation/data-management boundary, preserving the existing lock and channel responsibilities.

### 2.11 i18n wiring

`useI18n` supplies `t` and `locale` at `:177`; the root uses translations for toasts, status labels, and localized analysis timestamps (`:1725-1743`, `:1793-1795`). `I18nProvider` and `createI18nPreferenceSynchronizer` own preference storage ordering and `chrome.storage` synchronization. Feature modules may receive translated strings or a narrow translation function from presentation, but repositories/controllers must not import React i18n context.

## 3. Current Coupling Map

```text
I18nProvider
  -> SidepanelWorkspace
ExtensionProviders / RuntimeBridge
  -> videoContext, activeTabId, refresh, timestamp jump
SidepanelWorkspace
  -> workspace state + generation refs
  -> AnalysisTaskController + AskTaskController
  -> historyRepository + qaConversationRepository
  -> settingsStorage + applySidepanelDataMutation
  -> pending-history storage listener
  -> Overview / Transcript / Ask / Settings presentation
AnalysisTaskController
  -> Analysis runner supplied by SidepanelWorkspace
AskTaskController
  -> Ask runner supplied by SidepanelWorkspace
Analysis runner
  -> load-current-transcript -> runtime FETCH_VIDEO_TRANSCRIPT
  -> settingsStorage.resolveProvider -> runAnalysis
  -> historyRepository persistence
Ask runner
  -> qaConversationRepository + historyRepository QA cache
  -> askVideo
Runtime content bridge
  -> platform registry/adapter -> page DOM/fetch/runtime messages
History repository / QA repository
  -> Dexie schema / IndexedDB
Destructive coordinator
  -> Web Locks for serialization
```

The problematic coupling is not that repositories are imported; it is that one React function owns the sequencing and publication policy for all of them. The target separates sequencing by feature while retaining one canonical workspace publication boundary.

## 4. State Ownership Analysis

| State or behavior | Current owner | Kind | Cross-feature coupling | Target owner |
|---|---|---|---|---|
| Current `ActiveVideoContext`, `activeTabId`, runtime status | `ExtensionProviders` | Domain/runtime snapshot | Feeds every feature | Runtime bridge authoritative `runtimeContent`; workspace consumes a read-only projection |
| `contentKey`, platform, videoId, partId identity | Runtime/platform types and root refs | Domain identity | Analysis, transcript, history, Ask, navigation | `runtimeContent` from RuntimeBridge; WorkspaceController stores only the shared projection/reference |
| `activeTab` | `SidepanelWorkspace` | UI state | Layout only | Root/layout coordinator |
| Transcript cues/raw VTT/fingerprint/loading | Root callbacks/state | Domain snapshot + UI status | Analysis and Ask | `TranscriptController` snapshot |
| Selected analysis and analysis metadata | Root state | Domain snapshot | History, Ask, overview | `AnalysisController` snapshot; workspace stores only selected analysis identity/reference |
| Ask question/answer/thread/messages | Root state | Feature/domain snapshot | Analysis identity and transcript fingerprint | `AskController` snapshot; workspace stores only selected QA thread identity/reference |
| Recent history list | Root state | Feature read model | Overview and history restore | `HistoryController` read model |
| Provider metadata projection | Root state/settings callback | Domain projection | Analysis, Ask, header | `ProviderController` or existing settings boundary |
| Task phase/cancel/active task identity | Existing task controllers | Domain lifecycle | Banner and command enablement | Existing controllers, consumed through subscriptions |
| Generation counters | Root refs | Orchestration guard | All async workflows | Per-controller epochs plus workspace epoch |
| Destructive task snapshots and invalidation | Root + destructive coordinator | Cross-surface orchestration | History/data management/tasks | `DataManagementCoordinator` adapter |
| Toasts and localized status text | Root/presentation | UI presentation | All features | Presentation command result mapping |
| Runtime storage history-open event | Root effect | External event adapter | History/workspace | `HistoryOpenAdapter` |

The workspace must own only the minimum shared coordination contract: the authoritative runtime-content identity projection, display-selection references (selected analysis identity/reference and selected QA thread identity/reference), workspace epoch, and publication/reset policy. It must not copy complete transcript, analysis, or Ask snapshots from feature controllers. It must not own `activeTab`, provider secrets, IndexedDB handles, prompt construction, raw repository rows, arbitrary feature caches, or every feature's transient form state.

## 6. Module Responsibilities

### Root (`src/sidepanel/index.tsx`)

Keep only provider composition, controller construction, subscription wiring, active tab selection, layout props, and a small number of cross-feature selectors. It may map controller snapshots to presentation props and map command results to toasts. It must not contain repository calls, `chrome.*` listeners, prompt assembly, or multi-step persistence transactions.

### Workspace

`workspace-identity.ts` owns canonical identity construction and equality. `workspace-state.ts` defines the runtime-content projection, display-selection references, and workspace epoch. `workspace-controller.ts` consumes runtime-content transitions, handles historical publication requests, reset policy, and stale publication checks. It coordinates feature controllers but does not implement their repositories, model calls, or feature snapshots.

### Transcript

Own transcript loading policy: session/cache/remote precedence, captured `contentKey`, source-tab checks for tasks, fingerprint calculation, cache persistence, and transcript-specific errors. It may depend on the runtime transcript loader and history repository interfaces. It must not parse VTT or implement platform-specific fetching; those remain below the runtime/platform boundary.

### Analysis

Own Analysis command sequencing around the existing `AnalysisTaskController`: capture immutable task input, load transcript through the transcript controller, resolve provider at request time, consult cache, call `runAnalysis`, persist a run, and return a result tagged with source identity. It publishes to the workspace only through a typed publication callback guarded by identity/epoch.

### Ask

Own Ask preflight, thread selection, transcript fingerprint matching, bounded conversation context, QA cache, message append, and `AskTaskController` invocation. It may read the selected analysis and transcript snapshots through typed inputs. It must not mutate analysis state or synthesize a new canonical identity.

### History

Own recent-history read models, exact run aggregate loading, delete commands, and cross-surface pending-open consumption. It returns a `HistorySelection` or `HistoricalWorkspaceSnapshot`; workspace decides whether and when to publish it. History restore is not a second current-video acquisition path.

### Navigation

Own identity-aware timestamp jump command and normalized success/failure result. It calls the existing runtime bridge. Platform adapter seek and timestamp URL construction remain platform responsibilities.

### Settings/provider

Continue using `settingsStorage` and existing provider components. Expose metadata-only provider snapshots and a request-time `resolveProvider` capability. Provider secrets remain outside React and outside workspace state.

### Tasks

`task-presentation.ts` maps `ActiveAnalysisTask` and `ActiveAskTask` phases to banner/status view models. `ActiveAnalysisTaskBanner` and `ActiveAskTaskBanner` remain presentational and call controller cancellation commands.

## 7. Dependency Rules

### Allowed

- Presentation -> typed controller snapshots and commands.
- Root composition -> controllers, providers, and presentation components.
- Workspace controller -> feature controller interfaces and identity/value objects.
- Feature controllers -> domain services, repositories, runtime adapters, and task controllers.
- Transcript controller -> `load-current-transcript`, history transcript methods, and runtime transcript request interface.
- Analysis/Ask controllers -> request-time provider resolver and persistence interfaces.
- History controller -> `historyRepository` and pending-history adapter.
- Navigation service -> runtime bridge timestamp interface and `VideoIdentity`.
- Runtime content bridge -> platform registry/adapters and runtime message schemas.
- Repositories -> Dexie/IndexedDB and persistence schemas.

### Controller lifecycle contract

- Every controller or adapter exposing `subscribe()` must return an `unsubscribe()` function.
- Any controller/adapter that owns an external listener, channel, timer, or abortable resource must expose `dispose()` or `stop()` and make that operation idempotent.
- Root composition is responsible for constructing controllers, subscribing during mount, unsubscribing during unmount, and disposing/stopping owned resources during unmount.
- Side Panel unmount/reopen must not leave duplicated runtime listeners, storage listeners, BroadcastChannels, timers, or abortable work owned by the previous composition.
- This contract does not change the existing `AnalysisTaskController` or `AskTaskController` lifecycle semantics: their current task snapshots, cancellation rules, and non-cancellable `finalizing` phase remain authoritative.

### Forbidden

- Repository -> React, hooks, presentation components, or i18n context.
- Platform adapter -> Side Panel, React, IndexedDB, or provider settings.
- Feature controller -> UI component imports or direct toast calls.
- Presentation component -> IndexedDB, `chrome.runtime`, `chrome.storage`, or prompt construction.
- Search or future collection features -> a bag of all UI state; they must query canonical read-model interfaces.
- Workspace controller -> provider API keys, raw database rows, or every feature's form state.
- Any controller -> parsing VTT, hand-building YouTube/Bilibili URLs, or weakening `contentKey`/part identity.
- New code -> a second Web Locks/BroadcastChannel coordination mechanism.

## 8. Workspace Model

### A. What workspace is

Workspace is the current Side Panel session's shared coordination scope, not the entire application state and not a copy of every feature snapshot. Its minimum state is:

- `runtimeContent`: a read-only projection of the `ActiveVideoContext` supplied by `ExtensionProviders`/`RuntimeBridge` (`VideoIdentity` plus current runtime metadata such as title, author, canonical URL, active tab ID, and readiness). Workspace cannot assign an arbitrary different current `contentKey`.
- `displaySelection`: references describing what the user is viewing, such as selected analysis identity/reference, selected QA thread identity/reference, or a future bookmark/note reference. The complete transcript, analysis, and Ask snapshots remain owned by their feature controllers.
- `workspaceEpoch`: incremented on identity-changing transitions and invalidating old publication attempts;
- `publication/reset policy`: coordination rules for asking feature controllers to publish, reset, or reject a result.

`activeTab` is root/layout navigation state. It is not WorkspaceController state. Workspace or feature commands may return a navigation intent/recommended tab, which the root may apply. Content identity changes therefore preserve the user's current tab, matching V1 behavior.

Workspace should not contain complete feature snapshots, provider API keys, repository instances, prompt text, analysis cache rows, all recent history rows, task runner internals, toast state, i18n preference, or bookmark/note collections.

### F. Video switching and stale rejection

When RuntimeBridge reports a `runtimeContent` transition to a different `contentKey`, the workspace controller increments its epoch and instructs feature controllers to invalidate/reset their own feature state. It does not assign the new runtime identity itself. Feature controllers clear their owned current-content transcript, analysis, Ask, and error state through their own reset contracts. The workspace does not clear provider metadata, recent-history list, root-owned selected tab, i18n locale, or unrelated tasks.

The workspace controller owns the epoch increment. Each feature controller owns request-local generation and task identity checks. A result is publishable only when all applicable predicates hold:

1. the feature task/controller still owns the request `taskId`;
2. the request `contentKey` and, for Bilibili, `partId`, match the target workspace;
3. transcript fingerprint and analysis/thread identity still match;
4. the workspace epoch and transcript-load epoch are unchanged.

Persistence of a completed task always uses the captured source identity, even if the authoritative runtime content has switched. Only UI publication is conditional. This preserves `shouldPublishAnalysisToWorkspace` and the existing Analysis/Ask cancellation/finalizing semantics.

## 9. Task Coordination Boundary

### B. Side Panel coordination after independent task controllers

Side Panel still coordinates admission and presentation, but not lifecycle internals:

- build immutable task input from the current workspace and metadata-only provider profile;
- ask the existing controller to start/cancel and subscribe to snapshots;
- provide transcript and persistence capabilities to the feature runner;
- route completed feature results through workspace publication guards;
- expose active-task banners and disable conflicting commands;
- preserve destructive-operation admission and cross-surface invalidation.

It must not reimplement AbortController handling, phase transitions, task IDs, or cancellation rules already owned by `AnalysisTaskController` and `AskTaskController`.

### G. Bookmark and Notes extension point

Bookmarks and notes should be a separate knowledge feature controller keyed by `VideoIdentity` and optional `analysisRunId`/timestamp range. The controller returns bookmark/note read models and commands. Workspace supplies the current canonical identity and navigation service; the feature does not add its state to `workspace-controller.ts` and does not make `index.tsx` aware of persistence tables.

## 10. Runtime / Persistence Boundary

### E. `FETCH_VIDEO_TRANSCRIPT` orchestration

The runtime/content boundary remains responsible for platform acquisition:

1. Side Panel transcript/analysis controller requests a normalized transcript through `load-current-transcript`.
2. `load-current-transcript` sends `FETCH_VIDEO_TRANSCRIPT`, validates the response type, captured `contentKey`, optional source tab, and currentness.
3. `platform-content-bridge.ts` resolves the adapter, reads video metadata and transcript, rechecks the initial/current identity, and rejects changed parts.
4. The platform adapter owns DOM/API/VTT normalization and native platform behavior.
5. The transcript controller computes the fingerprint, chooses cache/session/remote precedence, and persists the normalized result.

Do not move this orchestration into `workspace-controller.ts` or a React effect. Do not create a second fetch path for Bookmark, Search, or Export.

### C. History restore ownership

History restore belongs to the history feature controller because it is a read of a selected historical aggregate, not a current-runtime acquisition. `historyRepository.getSavedAnalysisRunById` already returns the run, segments, run-bound transcript, and video record. The history controller should validate the requested selection and return a typed historical snapshot. The workspace controller owns the final publication/reset because only it can atomically replace the selected analysis, transcript, and QA identity. The root only wires `onSelectHistory`.

This avoids both incorrect alternatives: putting repository-specific restore logic in the root, or making the history feature mutate current workspace state directly.

### Runtime and persistence contracts

Controllers should depend on narrow interfaces, for example `TranscriptCacheReader`, `AnalysisRunRepository`, `QaConversationRepository`, and `TimestampNavigator`, rather than importing the entire repository singleton. Concrete repositories remain the only IndexedDB callers. This creates test seams without changing the V1 schema or migration.

## 11. Navigation Boundary

### D. Timestamp jump ownership

Timestamp jump belongs to a navigation service/controller at the Side Panel runtime boundary. It accepts a canonical `VideoIdentity` and seconds, calls `useRuntimeBridge().jumpToTimestamp`, and returns a normalized result for presentation. It is not a transcript concern because Analysis chapters, Ask citations, bookmarks, and future search results all jump by timestamp. It is not a platform adapter concern because the adapter owns the final native seek and URL mechanics behind the runtime bridge.

`formatTimestamp` remains a pure presentation helper or moves with the navigation view-model mapper. The identity passed to navigation must always come from the analysis/transcript/workspace snapshot, never from a bare `videoId`.

## 12. Migration Plan

Each stage is behavior-preserving, atomic, independently testable, and rollbackable. No stage depends on a future V1.1 feature.

### Stage 1: Characterization and pure identity helpers

Extract only the already-stable pure helpers: `formatTimestamp`, `identityFromContext`, `identityFromAnalysis`, and publication/comparator helpers whose inputs and outputs are explicit. Keep closure-based `isCurrent()` guards, state, and effects in their existing owners; do not mechanically abstract closures in this stage. Add characterization tests for YouTube identity, Bilibili P1/P2 identity, timestamp formatting, and analysis publication predicates. Rollback is deleting the new pure modules and restoring local imports.

### Stage 2: Task presentation boundary

Extract the mapping of `ActiveAnalysisTask`/`ActiveAskTask` phases to banner/header status into `tasks/task-presentation.ts`. Keep controller construction and subscriptions unchanged. Preserve active-task banner behavior, finalizing non-cancellation, cancellation messaging, and cross-tab task visibility. No persistence or runtime behavior moves.

### Stage 3: Navigation boundary

Extract `jumpWithIdentity`, `handleAnalysisJump`, and `handleTranscriptJump` behind `navigation/timestamp-navigation.ts`. The service receives a runtime navigator and toast/result mapper as dependencies. Preserve identity-aware seek, opened-new-tab behavior, and errors. This is the first browser-facing seam but requires no browser smoke claim.

### Stage 4: Transcript workflow boundary

Move `loadTranscriptForCurrent`, `loadTranscriptForTask`, fingerprint publication, and transcript-cache writes into a React-free `TranscriptController` or a controller with an explicit state adapter. Keep `load-current-transcript.ts`, the content bridge, and platform adapters unchanged. Add tests for session/cache/remote precedence, YouTube A -> B stale rejection, Bilibili P1 -> P2 rejection, current transcript reset, and fingerprint-driven Ask invalidation.

### Stage 5: History and Ask feature controllers

Extract history read/restore/delete commands and Ask conversation workflow behind typed controller interfaces. Keep the existing repositories and `AskTaskController` unchanged. The history controller returns snapshots; workspace performs publication. The Ask controller receives selected analysis/transcript identity and returns results tagged with thread/fingerprint identity. Preserve pending-history storage handoff, thread identity, cache identity, and finalizing/cancel semantics.

### Stage 6: Workspace ownership and root slimming

Introduce `workspace-state.ts` and `workspace-controller.ts` only after stages 1-5 have stable tests. Move identity transitions, epoch increments, reset policy, and publication guards first. Then reduce `index.tsx` to composition, subscriptions, navigation/layout coordination, and presentation props. Do not introduce a universal React context; use explicit controller interfaces and a small workspace snapshot.

## 13. Test Preservation Strategy

All existing V1 regression tests remain required. Each stage adds characterization only for behavior that is being moved.

| Stage | Tests to retain/add | Behavior locked before extraction |
|---|---|---|
| 1 | `current-video`, platform identity, cache identity, sidepanel UX tests; add pure helper tests | YouTube `youtube:<id>`, Bilibili `bilibili:<bvid>:p:<N>`, formatting, publish predicate |
| 2 | `analysis-task-controller`, `ask-task-controller`, active task component tests | one-active-task, task identity, phase updates, finalizing cannot cancel, banner visibility |
| 3 | runtime message/bridge tests, sidepanel component tests | analysis/transcript/citation jumps use canonical identity and preserve opened-tab result |
| 4 | `load-current-transcript`, fetch/adapter stale tests, transcript pipeline tests | YouTube A -> B, Bilibili P1 -> P2, cache/session/remote precedence, current-workspace reset |
| 5 | history repository/delete tests, QA repository/context/identity tests, pending-history tests | exact history restore, current workspace restore, Ask thread identity, cached answer identity, i18n/provider state unaffected |
| 6 | full existing suite plus new workspace transition and controller-lifecycle tests | active task persistence on original source, stale UI rejection, close/reopen reset behavior, provider projection, tab retention, unsubscribe/dispose behavior, and no duplicated listener after Side Panel reopen |

The following must be explicitly locked before Stage 6: Analysis completion persists to the original source after a video switch; Ask completion persists to the original thread and only updates matching workspace; cancel/finalizing semantics; history restore does not overwrite a newer workspace; i18n storage synchronization remains external; provider metadata changes update the default projection; timestamp jumps retain platform/part identity; every subscribed controller/adapter unsubscribes and disposes external resources; closing/reopening the Side Panel does not claim task durability beyond the documented Side Panel lifetime or leave duplicated listeners.

Browser smoke is not claimed by this design document. Static and automated test planning is the only verification scope here.

| Analysis Presets | `analysis/analysis-policy.ts` or `analysis-preset-repository` consumed by Analysis controller | Initial preset scope affects analysis semantics, prompt policy, or output preference; provider/model routing remains a separate future capability; UI selects an ID, never concatenates prompts |
| Editable Knowledge | Knowledge controller/repository, with explicit projection into analysis/history views | Store edits as knowledge-domain records; do not mutate canonical persisted analysis silently |
| Markdown Export | Export controller consuming typed analysis/transcript/knowledge read models | Reuse repository/export sanitizers; no direct IndexedDB from UI; preserve canonical identity in export metadata |
| Global Search | Search controller/repository query service | Query indexed read models for current video, historical analysis, bookmarks, notes, and QA threads by `contentKey`, `analysisRunId`, and thread identity; open results through workspace/history commands |

### H. Global Search opening rules

Search should return typed result variants: current-runtime-content result, historical-analysis result, bookmark/note result, and QA-thread result. Opening a result follows the authoritative runtime/display-selection rules:

- if `result.contentKey === runtimeContent.contentKey`, perform only feature selection plus a root-applied UI tab navigation intent;
- for historical analysis or QA, call `HistoryController` to load the run-bound snapshot, then let `WorkspaceController` coordinate publication across the feature controllers;
- if a Bookmark/Search result must open another real video, call `NavigationService` to open/jump to the target identity, then wait for RuntimeBridge to publish the new authoritative `runtimeContent` before any workspace transition; do not pre-seed or fake a different current workspace identity.

QA results additionally carry `threadId`, `analysisRunId`, and transcript fingerprint; the Ask controller verifies all three before opening. Bookmark/note results carry canonical identity and timestamp/range. No result may open by bare `videoId`, and Search must not import every UI state or write directly to `analysisView`, `qaThreadId`, or transcript state.

### I. Analysis Presets

The Analysis controller resolves a preset into an immutable execution policy immediately before task creation. In the initial extension point, the policy affects analysis semantics, prompt policy, or output preference. Provider/model routing is deliberately a separate future capability and is not implicitly owned by presets. The UI sends `presetId`; it never builds a provider prompt. Cache identity must include the effective preset/prompt version only if the preset changes analysis semantics; this is a future schema/cache-version decision and is outside this design-only task.

## 15. Risks / Anti-patterns

| Risk | Prevention |
|---|---|
| State duplication between workspace and feature controllers | One source of truth per state: feature controllers own complete feature snapshots; WorkspaceController owns only runtime-content projection, display-selection references, epoch, and publication/reset policy; root/presentation may subscribe to both |
| Stale closures after extraction | Keep refs/epochs inside the owning controller; pass captured identity into every async runner; test switch-during-request cases |
| Effect ordering regressions | Subscribe before initial reads where external state is involved; preserve i18n synchronizer ordering and make controller startup explicit |
| Circular dependencies | Workspace depends on feature interfaces; feature controllers depend on value objects/repositories, never on workspace implementation modules |
| Controller/UI ownership ambiguity | Commands are verbs with typed input/output; presentation receives snapshots and callbacks only |
| React rerender coupling | Subscribe to narrow snapshots; avoid a mega-context containing provider, transcript, analysis, Ask, history, and task state |
| Task identity drift | Reuse existing task controllers and immutable snapshots; never reconstruct task identity from current UI after start |
| Canonical identity drift | Centralize `VideoIdentity` constructors/comparators; require `contentKey` and Bilibili `partId` in feature commands |
| Hidden persistence writes | Repository methods are explicit; controllers document write points; presentation has no repository imports |
| History/workspace cross-update | History returns a snapshot/selection; workspace alone publishes or resets current selection |
| Over-generalized context | Use narrow interfaces and explicit props; no universal `WorkspaceContext` before measured need |
| Premature abstraction | Extract only after characterization tests and a stable responsibility; keep each stage independently rollbackable |
| Recreating Web Locks/BroadcastChannel logic | Keep `destructive-operation-coordinator` as the only coordination implementation and preserve its existing division of labor |
| Provider secret leakage into new modules | Pass metadata projections and a request-time resolver capability; never place API keys in workspace/task snapshots |
| Accidental schema/migration changes | Reuse current repository/schema contracts; V1.1 design and early refactors do not touch schema or migrations |
| Controller disposal/listener duplication | Require `unsubscribe()` from every subscription and idempotent `dispose()`/`stop()` for external listeners, channels, timers, and abortable resources; root owns teardown and add reopen/unmount characterization tests |

## 16. Explicit Non-goals

This design does not implement or design execution details for:

- ASR / Whisper;
- Vision / OCR;
- Cloud Sync;
- account systems;
- playlist batch analysis;
- cross-video Ask;
- schema migration implementation;
- UI redesign;
- dependency upgrades;
- Bookmark, Notes, Presets, Global Search, Export, or Editable Knowledge implementation.

It does not modify V1 release documentation, `TASK_STATE.md`, source code, tests, manifest, `package.json`, `bun.lock`, schema, or migration files.

## 17. Recommended First Refactor Task

**First task:** perform Stage 1 only: add characterization coverage and extract only stable pure identity/comparator/presentation helpers from `src/sidepanel/index.tsx`. The allowed extraction includes `formatTimestamp`, `identityFromContext`, `identityFromAnalysis`, and pure publication/comparator helpers with explicit inputs and outputs.

Do not move state, effects, task presentation, a navigation service, controller ownership, repository calls, or runtime messaging. Do not extract transcript workflow, move workspace/controller state, or abstract closure-based `isCurrent()` guards. Task-presentation, navigation, and transcript workflow remain separate later stages (Stages 2, 3, and 4 respectively). This task is independently testable and rollbackable without changing orchestration behavior.

## Final Decision

**DESIGN PASS**

The repository contains enough concrete evidence to define stable V1.1 boundaries. The design preserves the V1 correctness contracts: canonical `contentKey`/part identity, task IDs and cancellation/finalizing semantics, stale-response and generation guards, request-time provider resolution, history/run-bound transcript meaning, and the existing Web Locks/BroadcastChannel split. No additional information is required for this design-only decision.
