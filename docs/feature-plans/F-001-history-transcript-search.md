## 需求与边界

现有 Search 可以检索当前加载的字幕与分析、保存的分析、笔记和 Ask 对话，但不能搜索其他历史视频已保存的完整字幕。目标是让用户根据一句话或关键词找到**已本地保存的字幕片段**，看到来源视频、准确时间，并能打开原视频跳转。

**MVP 候选：** 沿用 NFKC、大小写归一化、空白分词 AND 的本地关键词检索；为结果提供视频标题、平台、分 P 身份、时间戳、字幕摘要；有界排序和分页/上限；根据真实 `contentKey` 开启视频和定位时间。

**非目标：** 未保存过的视频全网检索、自动下载整个播放列表、语义向量搜索、跨视频 Ask、ASR 与云端索引；不扩大默认权限。

## 设计评审前需要解决

- **真实数据源**：审查 `transcriptCache`、legacy `transcriptSnapshots` 的 cues 与删除保留语义；旧 `rawVtt` 可能到期，但 cues 仍供历史引用。需要测试是否有重复或损坏行。
- **身份**：YouTube 使用 `youtube:<videoId>`，Bilibili 必须精确到 `bilibili:<bvid>:p:<N>`，不允许按 bvid 合并 P1/P2；旧 `videoId` 的兼容处理需要写明。
- **性能与安全**：评估真实数据库大小、输入节流、分页与索引需求；搜索不发送 Provider 请求、不上传历史字幕；删除视频与 Clear All 应同步清理相关索引。
- **用户体验**：复用 Search 结果与跳转行为；切换视频期间避免陈旧结果跳到错误页面，且不干扰当前 Analysis / Ask 生命周期。
