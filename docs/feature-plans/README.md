# 单功能计划与进度管理

[返回功能路线图](../roadmap.md) · [复制计划模板](TEMPLATE.md)

**路线图登记 ID 和全局状态；计划文件记录具体决策、进度与证据。** 不另建相互矛盾的总账，也不把“建议优先”写成“已获授权”。

## 工作流

1. **提议（`candidate`）**：先在 `docs/roadmap.md` 登记稳定 `F-xxx` ID，必要时复制模板，填写用户场景、范围草案、风险。此阶段允许 Owner、Issue、版本为空。
2. **批准（`approved`）**：用户/维护者明确确认范围、验收标准、非目标、负责人与目标版本，并记录批准日期和依据；创建/关联 Issue，在计划与路线图同步变更。
3. **执行（`in_progress`）**：以明确的 Git 基线开分支，勾选真实完成的里程碑，追加实际进度日志、阻塞与下一步。重要功能的 RED/修复证据分开归档。
4. **审查（`in_review`）**：记录 PR、差异范围、目标与完整测试、类型检查、构建、必要的浏览器 Smoke、独立审查和 SHA256 证据。未执行的项目标 `NOT RUN`。
5. **交付（`done`）**：实际合并并通过批准的验收后，填入 Merge SHA、交付版本、剩余风险；同步变更路线图、README 与相关现行技术契约。
6. **暂停（`parked`）**：写清原因、决策者、恢复条件；不得仅因暂停清除既有失败或已完成记录。

进度日志**只追加**：日期、状态、已完成、证据（Issue / PR / commit / 日志）、阻塞与下一步。勾选具体里程碑而不是填写无依据的“90%”。每次计划状态更新，都应在同一 PR 同步 `docs/roadmap.md`。
