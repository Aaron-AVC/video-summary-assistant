# R-003 视频总结插件竞品测试协议（候选）

**版本**：2026-11-17 / v0.1 · **状态**：`PROTOCOL DRAFT — NOT RUN`
**被测对象**：本项目 V1.1、BiliScript、Glasp、Eightify、Video Flow、YouTube Bilibili AI Summarizer。
**原则**：在可比输入上测质量，不把商店文案当结果；不为了凑全覆盖而测试竞品明示不支持的网站。

## 1. 环境与证据

- 在全新隔离 Chrome / Edge 配置中分别安装各扩展，记录浏览器版本、扩展版本、安装来源、测试时间、地区/登录状态以及用到的 Provider（仅登记标识与模型，不登记 API Key）。
- 先在原生视频页面手工核实是否有可用字幕及字幕语言，然后保存来源视频 URL、ID、分 P、时长、字幕轨状态和代表性时间点，不将“页面无字幕”直接判成扩展错误。
- BYOK 扩展在可能时使用同一模型/Provider 与同一 API 参数；独立托管的商业 AI 按其默认公开套餐测试，**不将不同模型的回答质量差异归因于扩展本身**。
- 一项多角色要求单独测试两种模式：纯本地字幕/时间戳功能（不需 Provider）和启用 AI 后的生成质量/延迟。
- 隔离浏览器配置中不导入用户日常资料，不放入个人真实密码、浏览器 Cookie、长期 API 密钥和私有视频；临时测试凭据由用户本人输入且限制额度。完成后手动清理测试凭据/配置。
- 竞品流量与隐私仅记录实测网络行为；“开发者称不收集数据”记录为产品宣称，独立网络/源码核验另列。遵守平台和竞品使用条款。

## 2. 建议样本池：18 种可重复场景

本表列出**选择标准和测试 ID，不伪造已核验的视频链接**。确定样本后把实际 URL、字幕可用性、访问日期填入结果模板。共有 10 个 YouTube 场景、6 个 Bilibili 场景、2 个本地状态/权限回归场景。

| ID | 类型 | 样本条件与核心检查 |
| --- | --- | --- |
| Y-01 | YouTube | 3–15 分钟英文**人工字幕**：字幕、概要、时间戳跳转 |
| Y-02 | YouTube | 3–15 分钟中文**人工字幕**：标点和中文关键词检索 |
| Y-03 | YouTube | 10–30 分钟英文自动字幕：字幕完整性和误识别影响 |
| Y-04 | YouTube | 20–50 分钟中文自动字幕：长文本与中文总结 |
| Y-05 | YouTube | 30–60 分钟多语字幕视频：语言选择和输出语言 |
| Y-06 | YouTube | 60–120 分钟长课/访谈：分块、引用与延迟 |
| Y-07 | YouTube | 超过 120 分钟长视频：上限、错误、取消与资源开销 |
| Y-08 | YouTube | 经手工确认没有可访问字幕的视频：失败提示/回退 |
| Y-09 | YouTube | 连续从视频 A 导航到视频 B（SPA）：旧任务/旧字幕防串片 |
| Y-10 | YouTube | 同一视频重复运行：缓存、重新生成、历史恢复 |
| B-01 | Bilibili | BV 单 P、有效中文字幕：摘要/时间戳 |
| B-02 | Bilibili | BV 多 P 的 P1：提取分 P 身份和字幕 |
| B-03 | Bilibili | 同一 BV 的 P2：防止 P1/P2 数据混淆 |
| B-04 | Bilibili | 多轨或 AI 字幕：字幕选轨、语言与归一化 |
| B-05 | Bilibili | 无可用字幕（在同一测试会话下核实）：提示/回退 |
| B-06 | Bilibili | 多 P 内从 P1 切换 P2：进行中任务、跳转与历史隔离 |

## 3. 统计口径与公平对比

### 能力覆盖

- `eligible`：该产品官方支持该平台/功能、输入满足其公开前提且当前套餐可以执行。
- `unsupported`：官方明确不支持的功能或站点，计入**覆盖范围差异**，不直接计作失败。
- `blocked`：需付费/登录/地区权限而本轮未取得许可，单独记录。
- `attempted`：实际启动了该项操作，有完整结果或明确错误。

### 可重复指标（必须有原始记录）

- **字幕获取成功率** = 取得非空、可用时间戳字幕的次数 / 已尝试且平台原生字幕可用的次数。无字幕视频另记回退行为。
- **总结成功率** = 完成且结果非空、通过可观察结构校验的次数 / 实际点击生成的次数。区分模型失败、字幕失败、权限失败。
- **延迟**：记录从用户点击操作到可用字幕/完整总结的墙钟时长；首轮冷启动与第二次缓存命中**分别记录**，固定单位为秒。建议每个可比案例重复 3 次，报告中位数与分布，不先验承诺速度阈值。
- **引用/时间戳正确率**：每个成功总结至少人工抽查 3 条可定位主张/时间点；将其与原视频时刻及字幕上下文对照，逐条记录 `correct / partially correct / incorrect / unverifiable`，后者单独报告。
- **完成主要任务步骤数**：从空扩展配置到得到第一个带时间戳总结，计数用户交互步骤（不把打开基础浏览器网站计入）；新用户和已配置用户分开。
- **来源与隐私**：写明 Provider 是否由用户自行提供，字幕是否发给第三方、实际请求的 origin 及数据类别；仅在用户许可下用开发者工具检查，不采集 API Key、Cookie 或私人历史。
- **费用**：BYOK 记录 Provider 的实际计费信息（若可获得）；订阅产品记录订阅/试用条件与是否达到免费限制。不同模式分开呈现，不能强行计算“每次统一成本”。

**核心得分规则**：先给覆盖率，再给在“双方共同支持、同样字幕可用”的输入上的成功率和证据质量；时间与成本分开展示。不要以一个不透明权重综合成“谁最好”。

## 4. 执行顺序

1. 选定、验证和冻结样本列表、日期与账号/地区条件；对每个样本记录原生字幕状态。
2. 首先完成本项目基线的 18 类测试；在支持条件下对每个关键功能记录真实成功/失败和延迟。
3. 使用相同样本分别测试 Video Flow、BiliScript（仅其覆盖的 Bilibili）、Glasp、Eightify（仅其覆盖的 YouTube）、另一双平台 BYOK 插件。
4. 记录原始截图、测试日志和问题复现步骤到本机独立证据目录；可复核的脱敏结论再写入 [结果模板](video-benchmark-results-template.md)。
5. 根据失效率与操作成本修订 F-001/F-002/F-003/F-005 的候选优先级；只有明确批准后才立项并开发。

## 5. 故障与停止条件

出现 API Key / Cookie 暴露、插件请求异常陌生域名、无法解释的外发请求、异常高额计费迹象时，终止该工具的测试并隔离证据。遇到不稳定字幕/地区受限时保留完整上下文，标为 `INCONCLUSIVE`，换样本前不要覆盖失败记录。

**当前执行状态**：`NOT RUN`。本阶段只完成网页产品研究和代码/文档核对；尚无第三方扩展安装、账号登录、用户浏览器交互、生成质量或时间统计。
