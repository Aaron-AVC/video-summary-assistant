# VSA-R002-PR23 Design

## Intent

Create a reproducible record of the fixed-baseline Chrome MV3 production build, map actual Bundle Graph members to the accepted PR-1 provenance ledger, include closure-external shipped packages, and generate byte-preserving third-party notice previews for PR-4 review.

## Goals and constraints

- Keep `d596c2c366c5aa0d4538a6c7c274cc018eb7dc29` / tree `ba48847ee715df91932af7d102583580561e903a` as the product-source build baseline.
- Preserve the PR-1 ledger and its 74 directory identities, 70 required / 4 optional-only classifications, material bytes, and UNKNOWN constraint unchanged.
- Capture all bundles and their assets from the successful Parcel run used by the production build; bind graph, package/lock/ledger inputs, installed tool versions, manifest and output hashes.
- Record two additional graph identities and four additional generated-content sources. Cover all 74 closure identities conservatively while keeping notice coverage distinct from observed membership.
- Generate only an audit preview while `react-remove-scroll-bar@2.3.8` and other rights questions remain unresolved. A successful file generation is never a compliance PASS.
- Preserve exact legal text and component-level mappings. Do not change product behavior, dependencies, production manifest permissions, database schema, icon art, root LICENSE or licensing policy. Do not push, create a PR, merge or publish.

## Approaches considered

1. Use Plasmo's `--bundle-buddy` output. It is built into the pinned CLI, but its report contains dependency edges rather than complete per-bundle asset membership, so it does not meet the mapping requirement.
2. Rebuild with source maps or altered optimization settings. This changes build options and still does not make the evidence identical to the ordinary production output.
3. Instrument the pinned Plasmo 0.90.5 / Parcel 2.9.3 `Parcel.run()` result in-process, traverse every bundle including inline bundles, and hash the exact output files from that same run. This uses the supported success result and does not alter production config or build flags. **Selected** because it yields direct same-build evidence while preserving the ordinary production build settings.

## Design

A narrowly version-pinned Node preload captures the `buildSuccess` result returned by Plasmo's production `Parcel.run()`. It records package-directory identities, per-bundle source asset paths, package manifest hashes, output hashes and build input identities. A separate scope JSON links each PR-1 row to the graph, records positive attribution and unknown membership separately, and lists supplemental packages. A fail-closed validator checks these links and materials without relaxing the PR-1 validator. The generator consumes only validated inputs, writes to a caller-selected new directory, preserves exact license/NOTICE bytes, deduplicates bytes while retaining all component mappings, and labels any unresolved output as a blocked audit preview.

## Remaining evidence limits

`react-remove-scroll-bar@2.3.8` is confirmed in the options and sidepanel bundles, but its exact published tarball has no standalone LICENSE/NOTICE and its published gitHead is unavailable in the official upstream repository. The 2025 upstream LICENSE addition does not establish version-specific scope. Shadcn-derived template and copied icon attribution will be preserved with their existing evidence and open questions. These unresolved issues keep the notice output at audit-preview status.
